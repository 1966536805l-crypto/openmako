# OpenMako v0.1.0 Release Notes Draft

Do not publish this text until the v0.1 release checklist has passed on the
exact commit being tagged.

## Summary

OpenMako v0.1 audits supplied Evidence Court records for scope violations,
missing or failed validation evidence, and unsupported success claims.

This release is intentionally narrow: it is a record auditor and evidence
harness for coding-agent runs, not a replacement for coding agents.

## What Is Included

- `openmako evidence-court audit` for supplied JSON run records.
- `openmako evidence-court audit --json` for machine-readable reports using
  the `evidence-court/v0.1` schema version.
- `openmako evidence-court audit --ci` for CI failure behavior.
- `openmako evidence-court record from-jsonl` for converting simple JSONL event
  streams into audit records.
- `openmako evidence-court validate` for checking parser-accepted record input.
- A repository-local GitHub composite action for validating a supplied record,
  running an audit, writing `evidence-court-report.json`, and checking the
  expected exit code.
- A GitHub Actions demo workflow that audits a known-bad supplied record.

## Evidence To Check

- README public capability claims are guarded by `tests/test_public_metadata.py`.
- Evidence Court CLI behavior is guarded by `tests/test_cli_wrappers.py`.
- The focused learning-effect gate runs in `.github/workflows/focused.yml`.
- The Evidence Court demo runs in `.github/workflows/evidence-court-demo.yml`.
- Tagging requires `docs/release_checklist.md` to pass on the exact release
  commit.

## Boundary

v0.1 audits supplied records only. It does not yet ingest native Claude Code,
Codex, Cursor, or SWE-bench transcripts.

It also does not claim:

- broad unknown-repository SWE repair
- a published Marketplace GitHub Action
- full-suite or hidden benchmark results unless those exact commands were run
  on the release commit
- endorsement from internal planning docs or agent-written summaries
